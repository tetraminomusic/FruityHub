# Сервер и развёртывание

## Установка одной командой

Нужен VPS с Linux (Ubuntu/Debian) и доступ по SSH. Место на диске сервер почти не занимает: пользователи, проекты и последняя версия приложения (~25 МБ).

Из папки проекта, в Терминале на Mac:
```
./deploy/server-up.sh                  # на сервер из deploy/server.local (строка вида root@1.2.3.4)
./deploy/server-up.sh root@1.2.3.4     # на любой другой VPS
```
Скрипт заливает сервер, разворачивает, настраивает автозапуск и HTTPS и в конце показывает **адрес** (вида `https://1-2-3-4.sslip.io` — домен покупать не нужно), **код сервера** и **ключ администратора**. Всё это сохраняется в `server.txt` в корне проекта — никому его не отправляй.

* Если порт 443 уже занят (например, самим VPN), сервер встанет на `https://…:47943`; заняты 80 и 443 — на `http://<IP>:47900`. Порты в `ufw`/`firewalld`/`iptables` скрипт откроет сам; в панели хостинга, если там свой фаервол, их нужно открыть руками.
* Чтобы друзьям ничего не вписывать при регистрации, вшей адрес и код в сборку: `SERVER=<адрес> SERVER_CODE=<код> ./build.sh 0.7.0`.
* Логи на VPS: `journalctl -u uzbek-server -f`.

### Обновления приложения у всех
Галочка в настройках «Автоматически обновлять FruityHub» — новая версия ставится сама, но только когда ничего не передаётся и не синхронизируется (иначе FruityHub дождётся конца и перезапустится).

### Журнал сервера
Режим разработчика → «Логи сервера» (нужен ключ администратора): запросы с ошибками, каждая передача плагина (размер, скорость, обрывы), кто брал проекты в работу и ошибки, которые прислали приложения участников (галочка «Отправлять мои ошибки в журнал сервера» в настройках, включена по умолчанию; токены вырезаются). «Копировать» — чтобы вставить в чат, «Скачать файл» — весь журнал (`data/logs/server.log` на сервере).
1. `./build.sh 0.7.1` (номер версии — больше прошлого; можно добавить `NOTES="что нового"`).
2. `./deploy/server-up.sh` — вместе с сервером выкладывает собранные приложения из `dist/`.
3. У всех, у кого открыт FruityHub, появится плашка **«Доступно обновление»** → «Обновить и перезапустить»: приложение скачает новую версию, проверит её, заменит себя и откроется заново. На Windows, если exe лежит на общем рабочем столе, Windows один раз спросит разрешение.

Не выкладывать приложение, только обновить сервер: `./deploy/server-up.sh --no-update`.

### Бэкап и переезд на другой сервер
Всё, что знает сервер, лежит в одной папке `/var/lib/uzbek-server`: `db.json` (пользователи, проекты, приглашения), `server-code`, `admin-key`. Сервер сам делает копию `db.json` раз в сутки (`backups/`, 14 последних).
```
./deploy/server-up.sh backup                                   # скачать данные в server-backups/
./deploy/server-up.sh restore server-backups/….tar.gz root@НОВЫЙ  # поднять сервер на новом VPS с этими данными
```
Бэкап можно скачать и из приложения (режим разработчика → Сервер → «Скачать бэкап», файл .json — `restore` принимает и его). После переезда на **старом** сервере в админке впиши новый адрес в «Сервер переехал» — приложения сами переключатся, если новый сервер их узнаёт. Если у сервера свой домен, достаточно перенаправить домен — ничего переключать не нужно.

## Раскладка по Windows-ноутбукам в локальной сети

`deploy/deploy-windows.sh` (с Mac) кладёт `dist/FruityHub.exe` в установленный FruityHub каждого пользователя ноутбука (`C:\Users\<имя>\AppData\Local\Programs\FruityHub`), а где он ещё не установлен — на общий рабочий стол (при запуске покажет окно установки), через общий доступ к файлам (SMB), на все сразу. Адреса, логины и пароли ноутбуков — в `deploy/machines.local`, по строке `ip|логин|пароль` (файл не попадает в git; при первом запуске скрипт создаст заготовку).
```
./deploy/deploy-windows.sh                    # на все
./deploy/deploy-windows.sh 192.168.1.126      # на один
```
* Если FruityHub на ноутбуке ещё не установлен, файл попадает в `C:\Users\Public\Desktop`; старый «прога узбека.exe» оттуда убирается. Подробный журнал каждого ноутбука — `deploy/logs/<ip>.log`.
* На ноутбуках: сеть «Частная», включён «Общий доступ к файлам и принтерам». Для локальной (не Microsoft) учётки один раз выполнить там от имени администратора:
  `reg add HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System /v LocalAccountTokenFilterPolicy /t REG_DWORD /d 1 /f`
* Если что-то не так с одним ноутбуком — `./deploy/diagnose-windows.sh <ip>`.

## Сеть сервера: BBR и большие буферы
`install.sh` (его запускает `server-up.sh`) включает на VPS алгоритм TCP **BBR** с очередью **fq**, большие сетевые буферы (до 64 МБ) и отключает «остывание» соединения в паузах — файл `/etc/sysctl.d/90-fruityhub-net.conf`. На дальнем канале с потерями (например, до Финляндии) это заметно поднимает скорость передач через сервер. Настройки действуют на весь сервер, в том числе на VPN, если он там стоит. Не трогать сеть: `UZBEK_NO_TUNE=1` при установке, убрать — удалить этот файл и выполнить `sysctl --system`.

Если открыть адрес сервера в браузере — страница с иконкой FruityHub и надписью «Сервер работает» (адрес можно проверить так с любого устройства).
