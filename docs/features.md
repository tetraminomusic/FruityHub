# Что умеет FruityHub

## Регистрация: одно устройство — один пользователь
* При первом запуске: **ник**, свой **GitHub-токен** (Tokens (classic), галочки `repo` и `delete_repo`) и адрес и код сервера (если не вшиты). Сервер один раз сверяет, чей токен, и запоминает GitHub-логин; сам токен хранится только на твоём компьютере.
* **Люди** (окно «Плагины» → «Люди») — все зарегистрированные: кто в сети, GitHub-логин, система, делится ли плагинами; «Скачать всё, чего нет» — все плагины друга, которых нет у тебя, одним запросом.

## Проекты
* «Добавить проект» → папка с .flp. Папку можно просто **перетащить** из Finder / Проводника в список «Мои проекты».
* «Создать репозиторий и отправить»: на твоём GitHub появится приватный репозиторий для этого проекта. Галочка «Позвать всех пользователей» сразу приглашает остальных.
* **«Доступные»** — проекты, где ты участник, и все проекты твоего GitHub-аккаунта (созданные на других устройствах) и те, где ты коллаборатор, — которых ещё нет на этом компьютере.
* **Запустить проект** — открывает главный .flp в FL Studio. FruityHub сверяет версии: если проект сохранён в более новой FL Studio, чем установлена у тебя, предупредит.
* **Своё название** (✎ рядом с названием или меню проекта): меняется только на этом компьютере, папка, GitHub и сервер не трогаются. Там же — **артист**. Галочкой название и артист записываются в **Project info → Title / Author** внутри .flp. При добавлении проекта название папки попадает в Project info само, если там было пусто. Поменять название в .flp можно и во вкладке «Настройки» проекта.
* **Удалить файлы проекта** (меню проекта или «Настройки» проекта): вся папка уходит в Корзину, на GitHub и сервере проект остаётся.
* **Удалить репозиторий с GitHub** («Настройки» проекта, только владелец; подтверждение — вводом названия): репозиторий удаляется с GitHub навсегда, проект — с сервера, файлы на компьютерах остаются. Все репозитории, которые создал FruityHub, видны в Настройках → «Мои репозитории на GitHub»: там видно, какие нигде не используются (например, остались после оборванного создания), и их можно удалить. Для удаления у токена нужна галочка **delete_repo**.
* **Если создание репозитория оборвалось** (нет интернета, антивирус не дал запустить git…): в «Настройках» проекта или на экране подключения — «Создать репозиторий на GitHub…». FruityHub продолжит с уже созданным репозиторием, а не сделает второй.
* Позвать людей в проект — галочками из списка всех пользователей сервера (при создании, в «Участниках», в настройках проекта), ник руками вводить не нужно.
* Папки в списке проектов, перетаскивание проектов между ними.
* **Папку проекта перенесли или переименовали**: FruityHub помнит имя главного .flp и репозиторий проекта и раз в минуту ищет пропавшие проекты в «папках с проектами» (Настройки → Проекты) и рядом со старым местом. Нашлась одна подходящая папка — путь меняется сам; иначе на экране проекта — «Похоже, это она» и «Указать новое место…». Название, папка в списке и настройки проекта сохраняются.
* **Папки с проектами** (Настройки → Проекты): там же видно проекты FL Studio, которых ещё нет в списке, — «Добавить» по одному или все сразу.
* **Проверка перед отправкой**: если с диска пропало аудио, которое есть в отправленной версии, или проект ссылается на сэмпл, которого нет (часто это сэмплы внутри синтов — FL удаляет их как «неиспользуемые»), окно отправки предлагает «Вернуть и отправить»: файлы возвращаются из прошлой версии проекта (git) или из Корзины. То же — «Сэмплы» → «Вернуть пропавшие…». Файлы с галочкой «Отправлять» FruityHub не даёт удалить.
* **Сэмплы из прошлых версий**: если проект ссылается на сэмпл (в том числе изнутри плагина), которого нет ни в папке, ни по старому пути, а в прошлых версиях проекта он был, — при отправке, получении и скачивании проекта он сам достаётся оттуда.
* **Смена ника**: комментарии, задачи и статус хранят id автора на сервере, поэтому после смены ника они показываются под новым ником и остаются твоими (для старых записей — по истории ников на сервере).
* **Сколько места занимает проект** — под его названием: всё вместе, аудио и `.git` (история и вторые копии аудио Git LFS).
* **Неиспользуемое аудио — только у себя**: «Сэмплы» → выделить → «В корзину» → «Только у меня». Файл уходит в Корзину вместе с копией в `.git`, git перестаёт его замечать, git-lfs больше его не скачивает; на GitHub и у друзей он остаётся. «Вернуть все» скачивает обратно.
* **Выбор папки и картинки на Windows** — обычным окном Проводника; пока окно выбора открыто, второе не откроется.
* **Черновики**: текст в обсуждении, задачах и полях проекта не пропадает, когда переключаешься в другое окно или на другой проект.
* **Сортировка** (над списком «Мои проекты» и в Настройки → Вид): как добавлены, по названию А–Я / Я–А, по дате изменения — сначала свежие или давние. Дата изменения — когда последний раз сохраняли .flp (у себя или пришло от друга). Папки при сортировке по дате идут по самому свежему (или самому давнему) проекту внутри, пустые — в конце.

## Синхронизация (git + LFS)
* **Получить / Взять в работу / Отправить.** Пока проект «в работе», у друга горит красный баннер. Замок «в работе» хранится на сервере FruityHub (не в GitHub): взять и освободить — мгновенно, друзья видят это через пару секунд. При взятии FruityHub проверяет GitHub и скачивает изменения, только если они есть. «Отправить и освободить» освобождает проект уже после отправки. Проекты без сервера и старый сервер — по-старому, файлом в репозитории.
* .flp смерджить нельзя. Если вы правили одновременно, ничего не теряется: твоя версия сохранится копией `.flsync/conflicts/Трек (конфликт — …).flp`, в окне конфликта — «Открыть мою», «С GitHub», «Мою» или «Обе».
* Папка `Backup` (автосохранения FL) не отправляется — переключается в «Общих правилах» проекта.
* Сэмплы, лежащие вне папки проекта, при отправке копируются в `Audio/`, а у получателя пути в .flp направляются на них.
* **Аудио — с компьютера участника.** При скачивании проекта и «Получить» FruityHub сначала просит недостающие LFS-файлы (wav и т. п.) у участников, которые сейчас в сети: у кого они есть, присылает их по локальной сети напрямую или потоком через сервер; каждый файл проверяется по sha256. Что не пришло — докачивается с GitHub (в 8 потоков). Выключается в Настройки → Сеть.
* **Прогресс скачивания проекта**: шаг 1 — .flp и история, шаг 2 — аудио: файлы, мегабайты, скорость, откуда идёт.
* **Отменить скачивание** — кнопка на карточке задачи: git и передача аудио останавливаются, недокачанная папка удаляется.
* Один и тот же проект не скачивается двумя задачами сразу (приглашение + «Доступные»). Если папка проекта уже есть — в ошибке кнопки «Удалить папку и скачать заново» (в Корзину) и «Открыть его», если там тот же проект.
* Название и артист в Project info пишутся латиницей (FL не показывает кириллицу): «Кирюха» → «Kiryukha».

## Плагины — напрямую с компьютера на компьютер
* Вкладка «Плагины» проекта: таблица «плагин × участник», `PLUGINS.txt` в корне проекта.
* «Скачать у …» — один плагин, «Скачать у … всё недостающее» — все сразу. «Плагины → Люди → Чего у меня нет…» — сравнить с другом целиком. Если друг заранее разрешил скачивать у него плагины («участникам» или «всем»), FruityHub не переспрашивает — запрос уходит сразу.
* **Окно «Плагины»** (кнопка вверху): «Мои плагины» — все плагины на компьютере с поиском и фильтром по формату, у каждого «Проверить», «Зависимости», «Диагностика», «без пресетов» и «Удалить с этого компьютера» вместе с данными; «Люди»; «Передачи» — все передачи; «Настройки» — кто может скачивать плагины с моего компьютера, где FruityHub ищет плагины, «запрашивать недостающие при скачивании проекта».
* **Без библиотеки пресетов** (галочка в карточке плагина): при передаче придёт только сам плагин и то, без чего он не запустится. Получатель отвечает отправителю, что пресеты (файлы `.fxp`, `.vstpreset`, `.nksf`… и папки Presets / Patches / Banks) «уже есть», — они не передаются.
* **Сэмплы внутри плагинов** (Pigments, Serum, Kontakt…): пути к аудио ищутся и в сжатом (zlib/gzip) и base64-состоянии плагинов; если плагин хранит только имя файла — сэмпл ищется в библиотеках (Музыка, Документы, Arturia, Native Instruments…). Такие сэмплы при отправке копируются в `Audio/`, а у получателя кладутся туда, где их ищет плагин: тот же путь в его домашней папке или в системной папке производителя (если она у него есть).
* Плагин сам встаёт в папку своего формата **в ту же подпапку, что у отправителя** (`VST3\Arturia\DX7 V.vst3` → `VST3\Arturia\…`, папки создаются сами) и в базу плагинов FL. Если такой плагин уже есть в другой версии — он заменяется там, где лежит (старый уходит в резервную копию).
* **Что уходит вместе с плагином.** Его данные ищутся двумя способами:
  1. по имени — папки плагина и производителя в «Документах», AppData, ProgramData, Common Files, **Program Files** (на Mac — Application Support, `/Library/<Производитель>`);
  2. **разбором самого файла плагина**: таблица импорта (PE на Windows, Mach-O на Mac) — какие DLL/фреймворки он грузит; зашитые в бинарник пути (`Arturia\DX7 V\resources`, `%APPDATA%\…`, `/Library/…`); ключи реестра `SOFTWARE\<Производитель>\…` с путями (Windows).
  Библиотеки производителя кладутся рядом с плагином, пути из реестра записываются у получателя (только те, которых у него нет, пути из чужой папки пользователя переписываются на свою; для HKLM Windows спросит разрешение). Файлы интерфейса и ресурсов передаются всегда (у Arturia это, например, `gui-activation-generated.xml`), лицензии и значения реестра с ключами/серийниками — никогда.
* **Кэш**: что внутри каждого .flp (плагины, сэмплы, версия FL) хранится в `cache/flp-index.json` в папке настроек и пересчитывается, только если файл изменился; список установленных плагинов при запуске берётся из прошлого сканирования (`cache/plugins-scan.json`), а свежее сканирование идёт в фоне. «Пересканировать мои плагины» — сразу заново.
* **Карточка плагина**: в таблице «Плагины» только состояние у каждого и главное действие («Скачать»); нажми на плагин — откроется карточка: версии у всех, «Проверить», «Зависимости», «Переустановить у …», «Взять версию …», ссылка и файлы, история передач этого плагина.
* **Частичная установка**: если сам плагин встал, а что-то из его данных или путей — нет, у получателя это предупреждение с кнопкой «Попробовать ещё раз», в передачах — «установлен частично», а отправитель после передачи ждёт итога у получателя и показывает его как предупреждение, а не как ошибку передачи.
* **Arturia**: интерфейс плагинов Arturia лежит в папке ресурсов (`C:\ProgramData\Arturia\<плагин>\resources`, на Mac `/Library/Arturia/<плагин>/resources`); «Проверить» смотрит, есть ли она и окно активации `gui_xml/gui-activation-generated.xml`.
* «**проверить**» у своего плагина: пробная загрузка файла плагина в отдельном процессе (Windows: видно, каких DLL не хватает, не та разрядность, плагин отказывается стартовать), папки, на которые ссылается плагин и которых нет, архитектура, Visual C++, и стоит ли программа производителя для активации (Roland Cloud Manager, Arturia Software Center, Native Access, Waves Central, …).
* «**переустановить у …**» (и «переустановить» в списке передач, «Переустановить начисто» в отчёте): плагин и **все** его данные приходят заново, даже если такие файлы уже есть, и заменяют их (старые — в резервную копию `plugin-backups/…-данные`), пути в реестре перезаписываются.
* «**зависимости**» у плагина в таблице — что нужно плагину кроме его файла и что из этого уйдёт вместе с ним.
* После установки FruityHub проверяет, запустится ли плагин: не хватающие DLL/фреймворки, Visual C++ (в т. ч. старые 2010–2013), видеодрайвер, разрядность, активация.
* **Другая версия**: если у тебя плагин есть, а у друга версия другая — «Взять версию X у …» (в «Чего у меня нет…» такие тоже видны).
* **Зависимости не передаются повторно**: перед передачей отправитель присылает список файлов зависимостей, получатель отвечает, какие у него уже есть (лежат на месте, или библиотека уже есть в System32/PATH), — они не передаются. Если несколько плагинов передаются одновременно и у них общие файлы (общая папка производителя), каждый файл едет только один раз; если передача, с которой он должен был прийти, сорвалась — другая дозапрашивается сама.
* **Права администратора — один раз на установку**: плагин в Program Files, данные в системные папки, пути в HKLM и уборка старой копии выполняются одним запросом прав; при ошибке видна точная причина по каждому шагу, а данные сохраняются — кнопка «Попробовать ещё раз» в отчёте кладёт их без новой передачи.
* **Плагин не в той папке** (например, раньше лёг в `VST3\iZotope`) при новой передаче переезжает в правильную, старая копия уходит в резервную.
* **Сжатие zstd**: если у получателя новая версия FruityHub, архив плагина сжимается zstd вместо deflate — быстрее и плотнее; старые версии получают как раньше.
* **Докачка с места обрыва**: собранный архив плагина хранится у отправителя до конца передачи, а у получателя — уже полученное начало. При повторе (сам через 30 секунд или «Повторить») приходит только остаток — и через сервер, и по локальной сети. Брошенные файлы старше двух суток удаляются сами.
* **Скорость передачи**: потоки идут по HTTP/1.1 с большими буферами (у HTTP/2 на дальнем сервере скорость упиралась в окно), уже сжатые файлы не пережимаются, остальное — быстрым сжатием; в прогрессе видна скорость. Данные начинают уходить, только когда получатель подключился; если 90 секунд нет данных (сеть, сон ноутбука) — передача обрывается и повторяется, а не висит.
* **По локальной сети напрямую**: отправитель открывает временный порт и сообщает через сервер свои адреса в локальной сети и одноразовый ключ; получатель пробует подключиться напрямую — получилось, данные идут на скорости сети, мимо сервера; нет — через сервер (без ожидания: отправитель держит оба пути, какой выберет получатель — тем и идёт). Windows один раз спросит разрешение брандмауэра. Выключается в Настройки → Сеть.
* **Проверка скорости связи с сервером** (Настройки → Сеть): одно соединение и четыре сразу — видно, режет ли провайдер каждое соединение до зарубежного сервера.
* **Удалить у себя** (в карточке плагина): сам плагин (все копии), его данные и запись в базе плагинов FL — галочками, в Корзину; из защищённых папок — в резервную папку FruityHub с одним запросом прав.
* В «Плагинах» проекта — только передачи, запрошенные из этого проекта (тот же плагин для другого проекта — в «Плагины» → «Передачи»).
* **Отмена и повтор**: передачу можно отменить или прервать с любой стороны, неудачную или отменённую — «Повторить», установленную — «ещё раз». При выходе из FruityHub или обновлении во время передачи появится предупреждение.
* **Ссылка и файлы к плагину**: «+ ссылка / файл» в таблице — ссылка, заметка и небольшие файлы (до 50 МБ: пресеты, установщик бесплатной версии, инструкция). Файлы хранятся в репозитории проекта на GitHub (не тратят квоту LFS), друг скачивает их одним щелчком в «Загрузки».
* «Плагины» → «Настройки» → «Кто может скачивать плагины с моего компьютера». Передавайте только бесплатные плагины или те, на которые у второго есть своя лицензия.

## Метаданные трека и README
* Вкладка «Настройки» проекта → **«Трек»**: название, артист, альбом, год, номер, жанр, комментарий и **обложка** (JPG/PNG). Лежат в папке проекта — `Metadata/metadata.json` и `Metadata/cover.jpg`, — уходят участникам с отправкой. Название и артист заодно пишутся в Project info .flp (латиницей).
* **Рендеры подписываются сами**: когда FL Studio рендерит трек в папку проекта (новый WAV / MP3 / FLAC вне папок `Audio/` и `Backup/`, который проект не использует), FruityHub записывает в него метаданные и обложку: WAV — ID3 и LIST/INFO, MP3 — ID3v2.3, FLAC — Vorbis comment и PICTURE. Звук не трогается, старые теги заменяются. «В рендеры сейчас» — подписать все рендеры, включая старые.
* **README.md проекта** для GitHub собирается при каждой отправке: обложка, название, артист, альбом/год/жанр, версия FL, список плагинов. Если в проекте свой README (без пометки FruityHub) — он не трогается.
* Настройки → **Метаданные**: включить/выключить, в какие файлы (WAV, MP3, FLAC), вшивать ли обложку, подписывать ли старые рендеры, собирать ли README.

* **Длительность трека считается сама**: по красному выделению времени в плейлисте FL (событие 217 в .flp), а если его нет — до конца последнего клипа; при начальном темпе проекта. Своё значение можно вписать в «Трек».
* В «Трек» ещё **темп, тональность и длительность**. Темп сам подставляется из .flp — это темп в начале проекта (автоматизация темпа не учитывается, тогда основной темп лучше вписать самому). Всё это видно в шапке проекта, пишется в теги рендеров (TBPM/TKEY, BPM/INITIALKEY) и в README. У папки в списке проектов — общая длительность треков в ней.

## Язык
Настройки → Вид → **Язык**: русский или English. Интерфейс переводится по словарю `web/i18n_en.js`; сообщения, которые приходят от git и сервера, частично остаются по-русски. Проверить, что новые фразы интерфейса есть в словаре: `python3 scripts/i18n_check.py`.

## Настройки
Настройки разбиты на вкладки: **Профиль** (ник, «Как пользоваться», «Что нового»), **GitHub** (токен с прямой ссылкой на создание — галочки repo и delete_repo уже стоят, подсказка для тех, у кого нет GitHub, **расширения Git LFS** — один список на все проекты, мои репозитории), **Сеть** (проверка связи с сервером и его скорости, прокси для GitHub и проверка GitHub, передача по локальной сети, аудио от участников), **Метаданные**, **Вид** (язык, порядок проектов, **качество графики** — высокое: размытие, прозрачность, фон и плавные анимации; простое: без них и без видеокарты, меньше памяти — фон, сколько держать уведомления, кнопка «?», вернуть скрытые предупреждения), **Система** (git, проблемы, мешающие плагинам на Windows, режим разработчика), **Обновления**. Настройки обмена плагинами — в окне «Плагины». На экране не больше трёх уведомлений — остальные прокручиваются; перетащенная в окно папка добавляется с заставкой на весь экран.

При первом запуске показывается знакомство с программой (кнопка «?» вверху — открыть снова), после обновления — «Что нового».

Список проектов: цвет точки — актуально / есть твои неотправленные изменения / на GitHub новое / и то и другое / занят другом / без GitHub (подсказка при наведении); под названием — артист из Project info. Предупреждения в проекте («не найдено сэмплов», «проблемы с плагинами»…) закрываются крестиком — до тех пор, пока что-то не изменится. «Запустить проект»: правый клик или ▾ — выбрать версию FL Studio, если их несколько. При удалении репозитория — убрать проект из списка и/или удалить папку.

* **Фон**: своя картинка и степень затемнения.
* **Свои папки плагинов** («Плагины» → «Настройки»): «＋ Добавить папку…» (окно выбора) или перетаскиванием, удалить — «−».
* **Режим разработчика**: кнопка «Разработчик» вверху —
  * *Журнал команд*: какие команды git выполняет приложение, какие запросы уходят на сервер и GitHub, что нажато в интерфейсе, как закончились задачи (с временем). Фильтр, поиск, «только ошибки», копирование. Пишется и в файл `logs/fruityhub.log` в папке настроек; токены и ключи скрыты.
  * *Сервер* (нужен ключ администратора из `server.txt`): пользователи и проекты с удалением, очистка истории передач, бэкап, переезд, ручная выкладка обновления.
  * *Система*: версия, папки, найденные FL Studio.
