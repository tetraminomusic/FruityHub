# Что умеет FruityHub

## Регистрация: одно устройство — один пользователь
* При первом запуске: **ник**, свой **GitHub-токен** (Tokens (classic), галочки `repo` и `delete_repo`) и адрес и код сервера (если не вшиты). Сервер один раз сверяет, чей токен, и запоминает GitHub-логин; сам токен хранится только на твоём компьютере.
* **Люди** — все зарегистрированные: кто в сети, GitHub-логин, система, делится ли плагинами.

## Проекты
* «Добавить проект» → папка с .flp. Папку можно просто **перетащить** из Finder / Проводника в список «Мои проекты».
* «Создать репозиторий и отправить»: на твоём GitHub появится приватный репозиторий для этого проекта. Галочка «Позвать всех пользователей» сразу приглашает остальных.
* **«Доступные»** — проекты, где ты участник, и все проекты твоего GitHub-аккаунта (созданные на других устройствах) и те, где ты коллаборатор, — которых ещё нет на этом компьютере.
* **Запустить проект** — открывает главный .flp в FL Studio. FruityHub сверяет версии: если проект сохранён в более новой FL Studio, чем установлена у тебя, предупредит.
* **Своё название** (✎ рядом с названием или меню проекта): меняется только на этом компьютере, папка, GitHub и сервер не трогаются. Галочкой это же название записывается в **Project info → Title** внутри .flp. При добавлении проекта название папки попадает в Project info само, если там было пусто. Поменять название в .flp можно и во вкладке «Настройки» проекта.
* **Удалить файлы проекта** (меню проекта или «Настройки» проекта): вся папка уходит в Корзину, на GitHub и сервере проект остаётся.
* **Удалить репозиторий с GitHub** («Настройки» проекта, только владелец; подтверждение — вводом названия): репозиторий удаляется с GitHub навсегда, проект — с сервера, файлы на компьютерах остаются. Все репозитории, которые создал FruityHub, видны в Настройках → «Мои репозитории на GitHub»: там видно, какие нигде не используются (например, остались после оборванного создания), и их можно удалить. Для удаления у токена нужна галочка **delete_repo**.
* **Если создание репозитория оборвалось** (нет интернета, антивирус не дал запустить git…): в «Настройках» проекта или на экране подключения — «Создать репозиторий на GitHub…». FruityHub продолжит с уже созданным репозиторием, а не сделает второй.
* Позвать людей в проект — галочками из списка всех пользователей сервера (при создании, в «Участниках», в настройках проекта), ник руками вводить не нужно.
* Папки в списке проектов, перетаскивание проектов между ними.
* **Сортировка** (над списком): как добавлены, по названию А–Я / Я–А, по дате изменения — сначала свежие или давние. Дата изменения — когда последний раз сохраняли .flp (у себя или пришло от друга). Папки при сортировке по дате идут по самому свежему (или самому давнему) проекту внутри, пустые — в конце.

## Синхронизация (git + LFS)
* **Получить / Взять в работу / Отправить.** Пока проект «в работе», у друга горит красный баннер. Замок «в работе» хранится на сервере FruityHub (не в GitHub): взять и освободить — мгновенно, друзья видят это через пару секунд. При взятии FruityHub проверяет GitHub и скачивает изменения, только если они есть. «Отправить и освободить» освобождает проект уже после отправки. Проекты без сервера и старый сервер — по-старому, файлом в репозитории.
* .flp смерджить нельзя. Если вы правили одновременно, ничего не теряется: рядом появится `Трек (конфликт — …).flp`.
* Папка `Backup` (автосохранения FL) не отправляется — переключается в «Общих правилах» проекта.
* Сэмплы, лежащие вне папки проекта, при отправке копируются в `Audio/`, а у получателя пути в .flp направляются на них.
* **Аудио — с компьютера участника.** При скачивании проекта и «Получить» FruityHub сначала просит недостающие LFS-файлы (wav и т. п.) у участников, которые сейчас в сети: у кого они есть, присылает их по локальной сети напрямую или потоком через сервер; каждый файл проверяется по sha256. Что не пришло — докачивается с GitHub (в 8 потоков). Выключается в Настройки → Система.
* **Прогресс скачивания проекта**: шаг 1 — .flp и история, шаг 2 — аудио: файлы, мегабайты, скорость, откуда идёт.
* Один и тот же проект не скачивается двумя задачами сразу (приглашение + «Доступные»). Если папка проекта уже есть — в ошибке кнопки «Удалить папку и скачать заново» (в Корзину) и «Открыть его», если там тот же проект.
* Название и артист в Project info пишутся латиницей (FL не показывает кириллицу): «Кирюха» → «Kiryukha».

## Плагины — напрямую с компьютера на компьютер
* Вкладка «Плагины» проекта: таблица «плагин × участник», `PLUGINS.txt` в корне проекта.
* «Скачать у …» — один плагин, «Скачать у … всё недостающее» — все сразу. «Люди → Чего у меня нет…» — сравнить с другом целиком.
* Плагин сам встаёт в папку своего формата **в ту же подпапку, что у отправителя** (`VST3\Arturia\DX7 V.vst3` → `VST3\Arturia\…`, папки создаются сами) и в базу плагинов FL. Если такой плагин уже есть в другой версии — он заменяется там, где лежит (старый уходит в резервную копию).
* **Что уходит вместе с плагином.** Его данные ищутся двумя способами:
  1. по имени — папки плагина и производителя в «Документах», AppData, ProgramData, Common Files, **Program Files** (на Mac — Application Support, `/Library/<Производитель>`);
  2. **разбором самого файла плагина**: таблица импорта (PE на Windows, Mach-O на Mac) — какие DLL/фреймворки он грузит; зашитые в бинарник пути (`Arturia\DX7 V\resources`, `%APPDATA%\…`, `/Library/…`); ключи реестра `SOFTWARE\<Производитель>\…` с путями (Windows).
  Библиотеки производителя кладутся рядом с плагином, пути из реестра записываются у получателя (только те, которых у него нет, пути из чужой папки пользователя переписываются на свою; для HKLM Windows спросит разрешение). Файлы интерфейса и ресурсов передаются всегда (у Arturia это, например, `gui-activation-generated.xml`), лицензии и значения реестра с ключами/серийниками — никогда.
* **Кэш**: что внутри каждого .flp (плагины, сэмплы, версия FL) хранится в `cache/flp-index.json` в папке настроек и пересчитывается, только если файл изменился; список установленных плагинов при запуске берётся из прошлого сканирования (`cache/plugins-scan.json`), а свежее сканирование идёт в фоне. «Пересканировать мои плагины» — сразу заново.
* **Карточка плагина**: в таблице «Плагины» только состояние у каждого и главное действие («Скачать»); нажми на плагин — откроется карточка: версии у всех, «Проверить», «Зависимости», «Переустановить у …», «Взять версию …», ссылка и файлы, история передач этого плагина.
* **Частичная установка**: если сам плагин встал, а что-то из его данных или путей — нет, у получателя это предупреждение с кнопкой «Попробовать ещё раз», в передачах — «установлен частично», а отправитель после передачи ждёт итога у получателя и показывает его как предупреждение, а не как ошибку передачи.
* **Arturia**: интерфейс плагинов Arturia лежит в папке ресурсов (`C:\ProgramData\Arturia\<плагин>\resources`, на Mac `/Library/Arturia/<плагин>/resources`); «Проверить» смотрит, есть ли она и окно активации `gui_xml/gui-activation-generated.xml`.
* «**проверить**» у своего плагина: пробная загрузка файла плагина в отдельном процессе (Windows: видно, каких DLL не хватает, не та разрядность, плагин отказывается стартовать), папки, на которые ссылается плагин и которых нет, архитектура, Visual C++, и стоит ли программа производителя для активации (Roland Cloud Manager, Arturia Software Center, Native Access, Waves Central, …).
* «**переустановить у …**» (и «переустановить» в списке передач, «Переустановить начисто» в отчёте): плагин и **все** его данные приходят заново, даже если такие файлы уже есть, и заменяют их (старые — в резервную копию `plugin-backups/…-данные`), пути в реестре перезаписываются.
* «**зависимости**» у плагина в таблице — что нужно плагину кроме его файла и что из этого уйдёт вместе с ним.
* После установки FruityHub проверяет, запустится ли плагин: не хватающие DLL/фреймворки, Visual C++ (в т. ч. старые 2010–2013), видеодрайвер, разрядность, активация.
* **Другая версия**: если у тебя плагин есть, а у друга версия другая — «Взять версию X у …» (в «Чего у меня нет…» такие тоже видны).
* **Зависимости не передаются повторно**: перед передачей отправитель присылает список файлов зависимостей, получатель отвечает, какие у него уже есть (лежат на месте, или библиотека уже есть в System32/PATH), — они не передаются. Если несколько плагинов передаются одновременно и у них общие файлы (общая папка производителя), каждый файл едет только один раз; если передача, с которой он должен был прийти, сорвалась — другая дозапрашивается сама.
* **Права администратора — один раз на установку**: плагин в Program Files, данные в системные папки, пути в HKLM и уборка старой копии выполняются одним запросом прав; при ошибке видна точная причина по каждому шагу, а данные сохраняются — кнопка «Попробовать ещё раз» в отчёте кладёт их без новой передачи.
* **Плагин не в той папке** (например, раньше лёг в `VST3\iZotope`) при новой передаче переезжает в правильную, старая копия уходит в резервную.
* **Скорость передачи**: потоки идут по HTTP/1.1 с большими буферами (у HTTP/2 на дальнем сервере скорость упиралась в окно), уже сжатые файлы не пережимаются, остальное — быстрым сжатием; в прогрессе видна скорость. Данные начинают уходить, только когда получатель подключился; если 90 секунд нет данных (сеть, сон ноутбука) — передача обрывается и повторяется, а не висит.
* **По локальной сети напрямую**: отправитель открывает временный порт и сообщает через сервер свои адреса в локальной сети и одноразовый ключ; получатель пробует подключиться напрямую — получилось, данные идут на скорости сети, мимо сервера; нет — через сервер (без ожидания: отправитель держит оба пути, какой выберет получатель — тем и идёт). Windows один раз спросит разрешение брандмауэра. Выключается в Настройки → Система.
* **Проверка скорости связи с сервером** (Настройки → Система): одно соединение и четыре сразу — видно, режет ли провайдер каждое соединение до зарубежного сервера.
* **Удалить у себя** (в карточке плагина): сам плагин (все копии), его данные и запись в базе плагинов FL — галочками, в Корзину; из защищённых папок — в резервную папку FruityHub с одним запросом прав.
* В «Плагинах» проекта — только передачи, запрошенные из этого проекта (тот же плагин для другого проекта — в окне «Передачи»).
* **Отмена и повтор**: передачу можно отменить или прервать с любой стороны, неудачную или отменённую — «Повторить», установленную — «ещё раз». При выходе из FruityHub или обновлении во время передачи появится предупреждение.
* **Ссылка и файлы к плагину**: «+ ссылка / файл» в таблице — ссылка, заметка и небольшие файлы (до 50 МБ: пресеты, установщик бесплатной версии, инструкция). Файлы хранятся в репозитории проекта на GitHub (не тратят квоту LFS), друг скачивает их одним щелчком в «Загрузки».
* Настройки → «Кто может скачивать плагины с моего компьютера». Передавайте только бесплатные плагины или те, на которые у второго есть своя лицензия.

## Настройки
Настройки разбиты на вкладки: **Профиль** (ник, «Как пользоваться», «Что нового»), **GitHub** (токен с прямой ссылкой на создание — галочки repo и delete_repo уже стоят, подсказка для тех, у кого нет GitHub, прокси, мои репозитории), **Плагины** (кто может скачивать, где ищу, «запрашивать недостающие плагины при скачивании проекта», проверка системы), **Обновления**, **Вид** (фон, сколько держать уведомления, кнопка «?»), **Система** (передача по локальной сети, аудио от участников, проверка скорости, git, режим разработчика). На экране не больше трёх уведомлений — остальные прокручиваются; перетащенная в окно папка добавляется с заставкой на весь экран.

При первом запуске показывается знакомство с программой (кнопка «?» вверху — открыть снова), после обновления — «Что нового».

Список проектов: цвет точки — актуально / есть твои неотправленные изменения / на GitHub новое / и то и другое / занят другом / без GitHub (легенда под списком); под названием — артист из Project info. В настройках проекта — название и **артист** (Author) прямо в .flp, «Открыть репозиторий на GitHub». «Запустить проект»: правый клик или ▾ — выбрать версию FL Studio, если их несколько. При удалении репозитория — убрать проект из списка и/или удалить папку.

* **Фон**: своя картинка и степень затемнения.
* **Свои папки плагинов**: «＋ Добавить папку…» (окно выбора) или перетаскиванием, удалить — «−».
* **Прокси для GitHub**, проверка системы для плагинов, git / git-lfs.
* **Режим разработчика**: кнопка «Разработчик» вверху —
  * *Журнал команд*: какие команды git выполняет приложение, какие запросы уходят на сервер и GitHub, что нажато в интерфейсе, как закончились задачи (с временем). Фильтр, поиск, «только ошибки», копирование. Пишется и в файл `logs/fruityhub.log` в папке настроек; токены и ключи скрыты.
  * *Сервер* (нужен ключ администратора из `server.txt`): пользователи и проекты с удалением, очистка истории передач, бэкап, переезд, ручная выкладка обновления.
  * *Система*: версия, папки, найденные FL Studio.

## Клавиши
| | |
|---|---|
| Ctrl/⌘ + N | добавить проект |
| Ctrl/⌘ + Shift + N | новая папка в списке |
| Ctrl/⌘ + O | открыть папку текущего проекта |
| ↑ / ↓ | предыдущий / следующий проект |
| Tab / Shift + Tab | к следующей / предыдущей папке с проектами |
| Esc | закрыть окно (журнал, люди, настройки…) |
