# FruityHub

Приложение для совместной работы над проектами FL Studio (раньше называлось «прога узбека»). Внутри обычный git и Git LFS, но руками с ними работать не нужно: в окне три кнопки — **Получить**, **Взять в работу**, **Отправить**. Кроме них — кнопка **Запустить проект**, обсуждение проекта и обмен плагинами.

Устроено так:
* **Проекты — на GitHub:** у каждого свой GitHub-токен, один проект FL = один приватный репозиторий на GitHub того, кто его создал.
* **Свой сервер** (VPS) хранит пользователей (одно устройство — один пользователь), список проектов с участниками и приглашения, **передаёт плагины напрямую** с компьютера на компьютер (потоком, ничего не сохраняя) и **раздаёт обновления приложения**.

Готовые сборки — в разделе **Releases** (или после `./build.sh` в папке `dist/`):

| Кому | Файл |
|---|---|
| Windows | `FruityHub-Windows.zip` (внутри `FruityHub.exe`) |
| Mac (M1–M4) | `FruityHub-mac-AppleSilicon.zip` |
| Mac (Intel) | `FruityHub-mac-Intel.zip` |
| Сервер (Linux VPS) | `uzbek-server.tar.gz` (ставится скриптом `deploy/server-up.sh`) |

На Windows окно работает на WebView2: он встроен в Windows 10/11. Если его нет, FruityHub откроется во вкладке браузера.

При первом запуске новой версии настройки, регистрация и список проектов из «проги узбека» переносятся сами.

## Что умеет — коротко
* Проекты FL Studio в приватных репозиториях GitHub, история версий, конфликты без потерь (обе версии остаются).
* «Взять в работу» — друзья видят, кто сейчас занят проектом.
* Сэмплы сами собираются в папку проекта, пути в .flp поправляются у получателя.
* Плагины — с компьютера друга на свой одной кнопкой, вместе с данными и зависимостями; проверка, переустановка, удаление.
* Аудио и плагины в одной сети идут напрямую, аудио проекта можно брать у участников, а не только с GitHub.
* Обсуждение и задачи по проекту, статус, артист и название в Project info.
* Обновление приложения у всех с сервера.

Подробно: [docs/features.md](docs/features.md) · сервер и развёртывание: [docs/server.md](docs/server.md) · сборка и устройство кода: [docs/development.md](docs/development.md).

## Быстрый старт

1. Подними сервер: `./deploy/server-up.sh root@<твой VPS>` (подробно — [docs/server.md](docs/server.md)).
2. Запусти FruityHub: ник, GitHub-токен, адрес и код сервера.
3. Перетащи папку проекта в «Мои проекты» → «Создать репозиторий и отправить» (галочка «Позвать всех»).
4. Друг запускает FruityHub, регистрируется → у него появляется приглашение → «Принять и скачать».
5. Один раз в FL Studio обоим: *Options → File settings → Browser extra search folders* → папка со всеми проектами.

**Рабочий цикл:** `Получить → Взять в работу → Запустить проект → работаешь в FL, Ctrl/⌘+S → Отправить (освободить)`.

Exe и app не подписаны сертификатом разработчика. Windows может показать «Windows защитила компьютер»: «Подробнее» → «Выполнить в любом случае». Mac может спросить доступ к «Документам» и «Загрузкам»: нужно разрешить.

## Ограничения
* Бесплатный GitHub: **10 ГБ хранилища и 10 ГБ трафика Git LFS в месяц** на аккаунт владельца проектов.
* Плагин передаётся, только когда у обоих открыт FruityHub.
* Перетаскивание папки: окно приложения не сообщает, откуда папку перетащили, поэтому FruityHub ищет её на диске по имени и содержимому (несколько секунд). Если не нашёл — предложит выбрать вручную.

## Если на Mac приложение «не открывается»
Не заменяй его, перезаписывая файлы внутри старого `.app`: macOS убьёт его с «Code Signature Invalid». Удали старый `.app` целиком и скопируй новый (встроенное обновление делает именно так).
