# Программа Узбека

Программа для совместной работы над проектами FL Studio. Внутри обычный git и Git LFS, но руками с ними работать не нужно: в окне три кнопки — **Получить**, **Взять в работу**, **Отправить**. Кроме них есть обсуждение проекта, превью трека и обмен плагинами.

Это обычное приложение со своим окном и один файл без установки.

| Кому | Файл |
|---|---|
| Windows | `dist/Программа Узбека.exe` (или `dist/ProgrammaUzbeka-Windows.zip`): просто отправь другу |
| Mac (M1–M4) | `dist/mac-arm64/Программа Узбека.app` |
| Mac (Intel) | `dist/ProgrammaUzbeka-mac-Intel.zip` |

На Windows окно работает на WebView2: он встроен в Windows 10/11. Если его нет, программа откроется во вкладке браузера.

## Что умеет

### 0. Регистрация и друзья по нику
* При первом запуске указываешь **ник в программе**, GitHub-токен и **свой ник на GitHub**. Программа сверяет токен: если он от другого аккаунта, предупредит.
* Друзей в проекты зовут **по нику в программе**, а не по GitHub-логину. Соответствие «ник → GitHub» хранится в маленьком публичном справочнике на GitHub (репозиторий `programma-uzbeka-users`). Регистрация — это запись в нём. GitHub сам подтверждает, чей это аккаунт, а ник может занять только один человек.
  * Кто регистрируется **первым** и оставляет поле «Справочник ников» пустым, создаёт справочник на своём GitHub. Второй при регистрации вписывает в это поле GitHub-логин первого. Если собрать программу с `REGISTRY=<логин> ./build.sh`, справочник будет вшит и вписывать ничего не придётся.
* Приглашение **приходит прямо в программу**: слева сверху появится «📨 tetramino приглашает в проект…», дальше «Принять и скачать», и проект скачается.
* В «Настройках» проекта видно участников (ник + GitHub, кто ещё не принял приглашение), там же можно позвать кого-то ещё по нику.

### 0½. Вход с другого компьютера и «Доступные»
* **Один аккаунт на нескольких компьютерах.** На новом компьютере в окне регистрации выбери «Войти в свой аккаунт» и вставь GitHub-токен. Подтянутся ник, справочник ников, папки списка проектов (и какой проект в какой папке) и доверенные друзья. Эти настройки хранятся в приватном репозитории `programma-uzbeka-profile` на твоём GitHub и синхронизируются сами: поменял на одном компьютере — через пару минут то же на другом.
* **Вкладка «Доступные»** в списке слева показывает проекты на GitHub, где ты владелец или участник, которых ещё нет на этом компьютере. Кнопка «Скачать» — и проект скачан, без поиска ссылок. После входа на новом компьютере все твои проекты лежат там же, по своим папкам.
* **Участники существующего проекта** — кнопка «👥 Участники» в шапке проекта. Там список (ник, GitHub, кто ещё не принял приглашение), «Пригласить» по нику в программе или по GitHub-логину (если друг ещё не поставил программу) и «Убрать» / «Отменить приглашение» (только для владельца проекта).

### 1. Синхронизация проекта (git + LFS)
* **Получить / Взять в работу / Отправить.** Пока проект «в работе», у друга горит красный баннер.
* .flp смерджить нельзя. Если вы всё-таки правили одновременно, ничего не теряется: рядом появится `Трек (конфликт — …).flp`.
* Ход операций показывается **простыми сообщениями и полоской прогресса** в углу окна, без команд git. Если что-то пошло не так, будет понятный текст ошибки. Технические подробности спрятаны под ссылкой «Подробности для знающих».
* **📜 Журнал** — история событий: кто что отправил, что пришло с сервера, приглашения, плагины.

### 2. Готовый git-репозиторий
Если в добавленной папке уже есть git с сервером и участниками, программа **не перезаписывает его**. Она показывает карточку: сервер, ветку, историю, участников с никами, неотправленные изменения, что нового на сервере и аудио, лежащее в истории без LFS. Кнопка «Подключить как есть» сохраняет историю, сервер и участников и добавляет только служебные файлы программы.

### 3. Порядок в папке проекта
* **Всё аудио — в `Audio/`.** В корне остаются только `.flp`, `PLUGINS.txt` и служебные файлы. Аудио из корня автоматически переносится в `Audio/` (при добавлении проекта и перед отправкой), пути в .flp поправляются. Внешние сэмплы тоже копируются в `Audio/`.
* **Несколько проектов в одной папке.** Если рядом лежат два-три .flp, программа предупредит и предложит «Разобрать по папкам». Для каждого .flp выбираешь: главный, вынести в отдельный проект или «это версия, оставить». Аудио, нужное только вынесенному проекту, переезжает вместе с ним, общее копируется. Новые проекты сразу появляются в списке.
* **Удаление ненужного аудио.** Во вкладке «Сэмплы» есть список аудио, которое не используется ни одним .flp (неудачные дубли, старые рендеры). Его можно выделить и удалить **в корзину**, так что его можно вернуть. Используемые файлы программа удалить не даст.
* Совет для FL: *Project → General settings → Data folder* = папка `Audio` проекта, тогда новые записи сразу будут падать туда.

### 4. Плагины
* **Где программа их ищет:** база плагинов FL Studio (все папки, которые ты добавлял в FL), настройки FL, системный путь VST, стандартные папки и свои папки. Список с источниками есть в ⚙ Настройках.
* `PLUGINS.txt` и таблица «плагин × участник» показывают, у кого чего нет и где версии разные.
* **Скачать плагин у друга.** Рядом с плагином, которого у тебя нет, есть кнопка «🔌 Скачать у …». Без разрешения друга ничего не передаётся. В окне разрешения у друга программа сама проверяет, что можно отправить:
  * та же система → сам плагин, у тебя он **встанет автоматически**;
  * Mac ↔ Windows и в пакете плагина есть версия для обеих систем (так бывает у VST3) → тоже сам плагин;
  * иначе → **установщик**: программа ищет его в «Загрузках»/на рабочем столе друга, или друг выбирает файл (например, скачанный с сайта производителя для твоей системы). У тебя установщик скачается и запустится.
  * Можно поставить галочку «разрешать без вопросов»: тогда совместимые плагины этому человеку уходят автоматически.
  * Передавайте только бесплатные плагины или те, на которые у второго есть своя лицензия. Библиотеки сэмплов и активация не копируются.

### 5. Обсуждение и превью
* Вкладка «Обсуждение»: этап проекта, «что сейчас», заметки и задачи с галочками. Уходит на сервер сразу и не трогает файлы проекта.
* Один трек для прослушивания на проект (mp3/flac/wav), новый заменяет старый. Не тратит квоту LFS.

### 6. Список проектов
Проекты можно раскладывать по **папкам** (📁＋ внизу списка): «Альбом 2027», «Биты на продажу» и т. п. Проект перетаскивается мышкой или переносится через меню «⋯». Папки сворачиваются и есть только в программе, файлы на диске они не трогают.

## Быстрый старт

1. Запусти программу и зарегистрируйся: ник, GitHub-токен (classic, галочка `repo`; в окне есть ссылка), свой ник на GitHub.
2. «＋ Добавить проект» → папка с .flp → «Создать новый приватный репозиторий» → впиши **ник друга в программе**.
3. Друг запускает exe, регистрируется (в поле «Справочник ников» вписывает твой GitHub-логин), и у него появляется приглашение → «Принять и скачать».
4. Один раз в FL Studio обоим: *Options → File settings → Browser extra search folders* → папка со всеми проектами.

**Рабочий цикл:** `⤓ Получить → 🔒 Взять в работу → работаешь в FL, Ctrl/⌘+S → ⤒ Отправить (☑ освободить)`.

Exe и app не подписаны. Windows может показать «Windows защитила компьютер»: нужно нажать «Подробнее» → «Выполнить в любом случае». Mac может спросить доступ к «Документам» (база плагинов FL) и «Загрузкам» (поиск установщиков): нужно разрешить.

## GitHub или свой VPS?
Скорость упирается в домашний upload, а отправляются только новые файлы, поэтому VPS не даст ускорения в разы. Реальное ограничение — **квота Git LFS на бесплатном GitHub: 10 ГБ хранилища и 10 ГБ трафика в месяц**. Превью и передача плагинов эту квоту не тратят. Когда упрётесь в квоту, поднимите Forgejo/Gitea на VPS и поменяйте адрес сервера в настройках проекта. Превью и передача плагинов пока работают только с GitHub.

## Что лежит в репозитории проекта
```
Трек/
├── Трек.flp
├── Audio/                 ← всё аудио проекта (записи, сэмплы, внешние сэмплы)
├── PLUGINS.txt            ← плагины и у кого что стоит
└── .flsync/               ← настройки, манифест, инвентарь плагинов участников, lock.json
ветка flsync-meta          ← комментарии, статус, запросы плагинов (служебная)
релиз flsync-storage       ← превью трека и плагины «в пути» (черновик, служебный)
```

## Если на Mac программа «не открывается»
Программу нельзя заменять, перезаписывая файлы внутри старого `.app`: macOS запоминает подпись запущенного файла, и после такой перезаписи убивает приложение с «Code Signature Invalid». Обновляй, удаляя старый `.app` целиком и копируя новый (Finder делает именно так). Начиная с 0.4.0 бандл подписан целиком (ad-hoc).

## Сборка
Нужен Go 1.22+ и (для подписи Mac-версии) `rcodesign` или `codesign`. Собирается из любой ОС, C-компилятор не нужен:
```
REGISTRY=<твой GitHub-логин> ./build.sh 0.4.0   # → dist/ (REGISTRY можно не указывать)
go test ./...         # сквозные тесты: синхронизация, конфликты, справочник ников, приглашения, вход с другого компьютера, «Доступные», участники, Audio/, разделение проектов, корзина, комментарии, превью, передача плагинов
```
Тег `v*` на GitHub запускает сборку в Actions и выкладывает файлы в Releases.
