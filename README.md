# прога узбека

Прога для совместной работы над проектами FL Studio. Внутри обычный git и Git LFS, но руками с ними работать не нужно: в окне три кнопки — **Получить**, **Взять в работу**, **Отправить**. Кроме них есть обсуждение проекта, превью трека и обмен плагинами.

Устроено так:
* **Проекты — на GitHub, как и раньше:** у каждого свой GitHub-токен, один проект FL = один приватный репозиторий на GitHub того, кто его создал.
* **Свой сервер** (VPS) хранит пользователей (одно устройство — один пользователь), список проектов с участниками и приглашения, а ещё **передаёт плагины напрямую** с компьютера на компьютер: потоком, ничего не сохраняя у себя на диске.

| Кому | Файл |
|---|---|
| Windows | `dist/прога узбека.exe` (или `dist/ProgaUzbeka-Windows.zip`): просто отправь другу |
| Mac (M1–M4) | `dist/mac-arm64/прога узбека.app` |
| Mac (Intel) | `dist/ProgaUzbeka-mac-Intel.zip` |
| Сервер (Linux VPS) | `dist/server/` (там же `deploy-server.sh`) |

На Windows окно работает на WebView2: он встроен в Windows 10/11. Если его нет, прога откроется во вкладке браузера.

## Сервер: установка одной командой

Нужен VPS с Linux (Ubuntu/Debian) и доступ по SSH. Место на диске сервер почти не занимает: только список пользователей и проектов. Плагины через него идут потоком и не сохраняются.

На Mac (в Терминале), из папки `dist/server` сборки:
```
./deploy-server.sh root@<IP сервера>
```
Пароль от VPS спросят один раз. Скрипт сам определит архитектуру, скопирует сервер, настроит автозапуск и HTTPS и в конце покажет **адрес** (вида `https://1-2-3-4.sslip.io` — домен покупать не нужно) и **код сервера**. Они же сохранятся в `server.txt`. Есть свой домен — допиши его вторым словом: `./deploy-server.sh root@<IP> uzbek.мой-домен.ru`.

* Адрес и код вписываются в проге при регистрации (раздел «Сервер»). Чтобы друзьям ничего не вписывать, вшей их в сборку: `SERVER=<адрес> SERVER_CODE=<код> ./build.sh 0.6.0`.
* Код нужен, чтобы на твой сервер не регистрировались чужие.
* Обновить сервер — та же команда. Пользователи, проекты и код сохраняются.
* Логи на VPS: `journalctl -u uzbek-server -f`. Если порт 443 уже занят другим сайтом, сервер поднимется на `http://<IP>:47900`.

## Что умеет

### Регистрация: одно устройство — один пользователь
* При первом запуске: **ник**, свой **GitHub-токен** (Tokens (classic), галочка `repo`) и адрес и код сервера (если не вшиты в прогу). Сервер один раз сверяет, чей токен, и запоминает твой GitHub-логин; сам токен хранится только на твоём компьютере.
* Ник уникальный. Сменить ник или токен можно в ⚙ Настройках.
* **👥 Люди** — все зарегистрированные: кто в сети, GitHub-логин, система, делится ли плагинами.

### Проекты и участники
* «＋ Добавить проект» → папка с .flp → «Создать репозиторий и отправить»: на твоём GitHub появится приватный репозиторий для этого проекта. Можно сразу вписать ники друзей.
* Приглашение **приходит другу прямо в прогу** (слева сверху). Одновременно прога добавляет его на GitHub в репозиторий, а когда он жмёт «Принять и скачать», сама принимает приглашение GitHub и скачивает проект.
* **«Доступные»** — проекты на сервере, где ты участник, которых ещё нет на этом компьютере.
* **👥 Участники** в шапке проекта: позвать по нику, отменить приглашение, убрать участника (владелец; доступ на GitHub тоже снимается) или выйти самому.
* Проекты из прошлых версий (твой репозиторий на GitHub) показывают кнопку **«Подключить к серверу»**: репозиторий остаётся тем же, а те, у кого уже есть к нему доступ на GitHub и кто зарегистрирован в проге, сразу становятся участниками.

### Синхронизация (git + LFS)
* **Получить / Взять в работу / Отправить.** Пока проект «в работе», у друга горит красный баннер.
* .flp смерджить нельзя. Если вы правили одновременно, ничего не теряется: рядом появится `Трек (конфликт — …).flp`.
* Ход операций — простыми сообщениями и полоской прогресса, без команд git. **📜 Журнал** — история событий.

### Плагины — напрямую с компьютера на компьютер
* Вкладка «Плагины» проекта: таблица «плагин × участник», `PLUGINS.txt` в корне проекта.
* «🔌 Скачать у …» — один плагин, **«⬇ Скачать у … всё недостающее»** — все плагины проекта, которых у тебя нет, разом.
* **👥 Люди → «Чего у меня нет…»** — сравнить свои плагины со всеми плагинами друга, отметить нужные и скачать пачкой.
* **Передача прямая:** как только владелец разрешил (или разрешил заранее в настройках), его прога отправляет плагин потоком через сервер прямо в твою прогу — на сервере ничего не сохраняется. Поэтому у обоих должна быть открыта прога; если друг не в сети, плагин уйдёт сам, когда он появится. **🔌 Передачи** — все запросы и их статусы.
* **Плагин сам встаёт куда нужно:** в папку, где у тебя уже лежат плагины этого формата (VST3, VST2, CLAP, AU). Если это защищённая папка Windows (Program Files), Windows один раз спросит разрешение. Кроме того, прога переносит записи о плагине из базы плагинов FL друга (Plugin database) в твою, с твоим путём — FL видит плагин без пересканирования (если FL был открыт, перезапусти его).
* **⚙ Настройки → «Кто может скачивать плагины с моего компьютера»**: никому / спрашивать каждый раз / участникам моих проектов без вопросов / всем без вопросов. Установщики (когда системы разные и в пакете нет версии для системы друга) всё равно требуют подтверждения; полученный установщик лежит в «Загрузках», прога предложит его запустить.
* Передавайте только бесплатные плагины или те, на которые у второго есть своя лицензия. Библиотеки сэмплов и активация не копируются.

### Порядок в папке, обсуждение, превью
* Всё аудио — в `Audio/`, в корне только `.flp`, `PLUGINS.txt` и служебное. Несколько .flp в одной папке — «Разобрать по папкам». Неиспользуемое аудио можно удалить в корзину.
* «Обсуждение»: этап проекта, заметки и задачи. Один трек-превью на проект (mp3/flac/wav).
* Проекты в списке раскладываются по папкам (📁＋).

## Быстрый старт

1. Подними сервер: `./deploy-server.sh root@<IP>` (см. выше).
2. Запусти прогу: ник, GitHub-токен, адрес и код сервера.
3. «＋ Добавить проект» → папка с .flp → впиши ник друга → «Создать репозиторий и отправить».
4. Друг запускает прогу, регистрируется → у него появляется приглашение → «Принять и скачать».
5. Один раз в FL Studio обоим: *Options → File settings → Browser extra search folders* → папка со всеми проектами.

**Рабочий цикл:** `⤓ Получить → 🔒 Взять в работу → работаешь в FL, Ctrl/⌘+S → ⤒ Отправить (☑ освободить)`.

Exe и app не подписаны сертификатом разработчика. Windows может показать «Windows защитила компьютер»: «Подробнее» → «Выполнить в любом случае». Mac может спросить доступ к «Документам» (база плагинов FL) и «Загрузкам» (поиск установщиков): нужно разрешить.

## Ограничения
* Бесплатный GitHub: **10 ГБ хранилища и 10 ГБ трафика Git LFS в месяц** на аккаунт владельца проектов. Превью и плагины эту квоту не тратят.
* Плагин передаётся, только когда у обоих открыта прога. Скорость — как у самой медленной из двух интернет-линий.

## Если на Mac прога «не открывается»
Не заменяй прогу, перезаписывая файлы внутри старого `.app`: macOS убьёт её с «Code Signature Invalid». Удали старый `.app` целиком и скопируй новый.

## Сборка
Нужен Go 1.22+ и (для подписи Mac-версии) `rcodesign` или `codesign`. Собирается из любой ОС, C-компилятор не нужен:
```
SERVER=<адрес> SERVER_CODE=<код> ./build.sh 0.6.0   # → dist/ (адрес и код можно не вшивать)
go test ./...      # сервер, регистрация, проекты, приглашения + GitHub, прямая передача и установка плагинов, база плагинов FL, подключение старых проектов, синхронизация, конфликты, Audio/, комментарии, превью
```
Картинки интерфейса: `web/bg.jpg` (фон) и `web/icon.png`; иконка приложения — `assets/icon.*` (для Windows ещё `rsrc_windows_amd64.syso`).
