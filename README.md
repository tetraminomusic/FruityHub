# прога узбека

Прога для совместной работы над проектами FL Studio. Внутри обычный git и Git LFS, но руками с ними работать не нужно: в окне три кнопки — **Получить**, **Взять в работу**, **Отправить**. Кроме них есть обсуждение проекта, превью трека и обмен плагинами.

Устроено так:
* **Свой сервер** (VPS) хранит пользователей, проекты и участников, приглашения и передаёт плагины между компьютерами.
* **Сами проекты FL лежат на GitHub** — в одной бесплатной организации. Место на сервере они не занимают, а GitHub-аккаунт участникам не нужен: сервер выдаёт проге временный ключ ровно к тому проекту, в котором ты участник.

| Кому | Файл |
|---|---|
| Windows | `dist/прога узбека.exe` (или `dist/ProgaUzbeka-Windows.zip`): просто отправь другу |
| Mac (M1–M4) | `dist/mac-arm64/прога узбека.app` |
| Mac (Intel) | `dist/ProgaUzbeka-mac-Intel.zip` |
| Сервер (Linux VPS) | `dist/uzbek-server.tar.gz` |

На Windows окно работает на WebView2: он встроен в Windows 10/11. Если его нет, прога откроется во вкладке браузера.

## Сервер: установка один раз

Нужен VPS с Linux (Ubuntu/Debian), открытые порты 80 и 443. Сервер почти не ест места: только список пользователей и плагины «в пути» (до 5 ГБ одновременно, лишнее удаляется через 72 часа).

1. Скопируй архив на VPS и запусти установку:
   ```
   scp dist/uzbek-server.tar.gz root@<IP>:
   ssh root@<IP> 'tar xzf uzbek-server.tar.gz && bash server/install.sh'
   ```
   Если у тебя есть домен — `bash server/install.sh uzbek.мой-домен.ru` (A-запись должна смотреть на VPS). Без домена адрес будет вида `https://1-2-3-4.sslip.io`. HTTPS-сертификат получится сам.
2. Скрипт напечатает ссылку `https://…/setup?key=…`. Открой её в браузере:
   * создай бесплатную **организацию на GitHub** (ссылка есть на странице), впиши её название;
   * нажми «Создать GitHub App» → GitHub попросит подтвердить → затем «Install» → **All repositories**;
   * появится «Готово ✓».
3. Адрес сервера можно вшить в прогу, чтобы друзьям ничего не вписывать: `SERVER=https://… ./build.sh 0.5.0`. Без этого адрес вписывается один раз при регистрации (в окне регистрации, раздел «Сервер»).

Повторный запуск `install.sh` обновляет сервер, пользователи и проекты сохраняются (`/var/lib/uzbek-server`). Логи: `journalctl -u uzbek-server -f`.

## Что умеет

### Регистрация: одно устройство — один пользователь
* При первом запуске придумываешь **ник** — и всё. Паролей и токенов нет: аккаунт привязан к этому компьютеру (ключ хранится в настройках проги). Ник уникальный, сменить его можно в ⚙ Настройках.
* **👥 Люди** — все зарегистрированные: кто в сети, какая система, делится ли плагинами.

### Проекты и участники
* «＋ Добавить проект» → папка с .flp → «Создать на сервере и отправить», можно сразу вписать ники друзей.
* Приглашение **приходит прямо в прогу** (слева сверху): «Принять и скачать» — и проект скачан. Можно отказаться.
* **«Доступные»** — проекты на сервере, где ты участник, которых ещё нет на этом компьютере.
* **👥 Участники** в шапке проекта: позвать по нику, отменить приглашение, убрать участника (владелец) или выйти самому. Убранный участник сразу теряет доступ к проекту на GitHub.
* Проекты из старой версии (на личном GitHub) показывают кнопку **«Перенести на сервер»**: история, аудио и обсуждение переедут, старый репозиторий останется как был.

### Синхронизация (git + LFS)
* **Получить / Взять в работу / Отправить.** Пока проект «в работе», у друга горит красный баннер.
* .flp смерджить нельзя. Если вы правили одновременно, ничего не теряется: рядом появится `Трек (конфликт — …).flp`.
* Ход операций — простыми сообщениями и полоской прогресса, без команд git. **📜 Журнал** — история событий.

### Плагины — через сервер
* Вкладка «Плагины» проекта: таблица «плагин × участник», `PLUGINS.txt` в корне проекта.
* «🔌 Скачать у …» — один плагин, **«⬇ Скачать у … всё недостающее»** — все плагины проекта, которых у тебя нет, разом.
* **👥 Люди → «Чего у меня нет…»** — сравнить свои плагины со всеми плагинами друга, отметить нужные и скачать пачкой.
* **⚙ Настройки → «Кто может скачивать плагины с моего компьютера»**: никому / спрашивать каждый раз / участникам моих проектов без вопросов / всем без вопросов. В режимах «без вопросов» твоя прога сама упаковывает и отправляет плагин, а у друга он сам скачивается и ставится — никто ничего не нажимает. Установщики (когда системы разные и в пакете нет версии для системы друга) всё равно требуют подтверждения.
* Между Mac и Windows плагин переносится, если в его пакете есть версия для обеих систем (так бывает у VST3), иначе отправляется установщик — прога ищет его в «Загрузках», или его можно выбрать. **🔌 Передачи** — все запросы и их статусы.
* Передавайте только бесплатные плагины или те, на которые у второго есть своя лицензия. Библиотеки сэмплов и активация не копируются.

### Порядок в папке, обсуждение, превью
* Всё аудио — в `Audio/`, в корне только `.flp`, `PLUGINS.txt` и служебное. Несколько .flp в одной папке — «Разобрать по папкам». Неиспользуемое аудио можно удалить в корзину.
* «Обсуждение»: этап проекта, заметки и задачи. Один трек-превью на проект (mp3/flac/wav).
* Проекты в списке раскладываются по папкам (📁＋).

## Быстрый старт

1. Подними сервер (см. выше).
2. Запусти прогу, придумай ник (при необходимости впиши адрес сервера).
3. «＋ Добавить проект» → папка с .flp → впиши ник друга → «Создать на сервере и отправить».
4. Друг запускает прогу, регистрируется → у него появляется приглашение → «Принять и скачать».
5. Один раз в FL Studio обоим: *Options → File settings → Browser extra search folders* → папка со всеми проектами.

**Рабочий цикл:** `⤓ Получить → 🔒 Взять в работу → работаешь в FL, Ctrl/⌘+S → ⤒ Отправить (☑ освободить)`.

Exe и app не подписаны сертификатом разработчика. Windows может показать «Windows защитила компьютер»: «Подробнее» → «Выполнить в любом случае». Mac может спросить доступ к «Документам» (база плагинов FL) и «Загрузкам» (поиск установщиков): нужно разрешить.

## Ограничения
* Бесплатная организация GitHub: **10 ГБ хранилища и 10 ГБ трафика Git LFS в месяц** на все проекты вместе. Превью и передача плагинов эту квоту не тратят.
* Один плагин или установщик — до 1,5 ГБ.

## Если на Mac прога «не открывается»
Не заменяй прогу, перезаписывая файлы внутри старого `.app`: macOS убьёт её с «Code Signature Invalid». Удали старый `.app` целиком и скопируй новый.

## Сборка
Нужен Go 1.22+ и (для подписи Mac-версии) `rcodesign` или `codesign`. Собирается из любой ОС, C-компилятор не нужен:
```
SERVER=https://<адрес сервера> ./build.sh 0.5.0   # → dist/
go test ./...      # сервер, регистрация, проекты, приглашения, доступ к GitHub, передача плагинов, перенос старых проектов, синхронизация, конфликты, Audio/, комментарии, превью
```
Картинки интерфейса: `web/bg.jpg` (фон) и `web/icon.png`; иконка приложения — `assets/icon.*` (для Windows ещё `rsrc_windows_amd64.syso`).
